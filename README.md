# CSFM Strut and Tie Surrogate

Dataset-generation pipeline, generated dataset, trained model weights and
evaluation code for a neural-network surrogate of a discrete strut and tie
solver that applies the Compatible Stress Field Method (CSFM) constitutive
laws to concrete discontinuity regions (D-regions).

A per-archetype neural network maps the design parameters of a D-region
(deep beam, hammerhead pier, multi-column bent, pile cap) to its failure
load factor and to the strut and tie member forces at the failure state, as
computed by the reference solver, which applies compression softening of the
struts and tension stiffening of the ties on a fixed truss. A bagged deep
ensemble with split-conformal calibration attaches a finite-sample
prediction interval to the failure load and to every member force; a
least-squares projection makes the predicted force state exactly
equilibrated; an ensemble-spread flag marks out-of-domain designs. The
reference solver is checked against two experimental series (five pier caps
of Geevar and Menon, eight deep beams of Li et al. 2022).

## Contents

```text
solver/        TypeScript reference solver (src/core) and the sweep scripts
  scripts/exportDataset.ts        Latin-hypercube sweep -> data/dataset.json
  scripts/exportExtrapolation.ts  out-of-domain shells
  scripts/exportVariant.ts        two-point-load deep beam (changed configuration)
  scripts/verifyDesign.ts         solver check of surrogate-chosen designs (stdin JSON)
  scripts/validatePiercaps.ts     solver vs Geevar and Menon pier caps
  scripts/validateLiBeams.ts      solver vs Li et al. (2022) deep beams
  scripts/timeSolver.ts           per-design solver timing
data/          gzipped datasets (see data/README.md for the schema)
validation/    pier-cap benchmark JSON and notes
pinn/          PyTorch surrogate: training, evaluation, uncertainty, figures
  runs/<archetype>/model.pt       trained single networks (5 archetypes)
  runs/<archetype>/ensemble/      10 bagged members per archetype (4 archetypes)
experiments/   additional experiments E1-E8 with their logs and JSON results
figures/       vector figures regenerated by the scripts
```

## Installation

Python >= 3.10 with `torch >= 2.2`, `numpy`, `scikit-learn`, `matplotlib`,
`scipy` (versions used for the reported numbers: torch 2.2.2, numpy 1.26.4,
scikit-learn 1.4.1, matplotlib 3.10.1, scipy 1.15.2; CPU only):

```sh
python -m venv .venv && source .venv/bin/activate
pip install -r pinn/requirements.txt scikit-learn matplotlib scipy
```

Node >= 20 for the solver (`tsx` runs the TypeScript directly):

```sh
cd solver && npm install
```

## Reproducing the results

Run from `pinn/` unless stated. The trained checkpoints reproduce the
results without retraining; scripts that retrain take seconds to minutes on
a laptop CPU (one 400-epoch network trains in about 4 s).

| Command | Reproduces |
|---|---|
| `python evaluate.py --archetype deepBeam` (and `hammerhead`, `multiColumnBent`, `pileCap`) | failure-load accuracy: MAPE 5.6 / 4.3 / 2.9 / 4.9 %, R2 0.964 / 0.983 / 0.994 / 0.957 |
| `python force_equilibrium.py` | member-force accuracy: force R2 0.994-0.997, equilibrium residual 1.2-1.8 % |
| `python ../experiments/e3_equilibrium_projection.py` | exact equilibrium by projection; static determinacy of the trusses |
| `python timing_surrogate.py` and `cd ../solver && npm run timing` | surrogate and solver timing |
| `python baselines.py` | seven tabular baselines |
| `python ablation.py` | force-loss weight ablation |
| `python ../experiments/e2_weq_sweep.py` | equilibrium-weight sweep |
| `python censoring.py` and `python ../experiments/e5_censored_loss.py` | non-failing designs: classification and a one-sided hinge loss |
| `python make_ensemble.py`, `python calibration.py` | conformal calibration of the failure load |
| `python ../experiments/e7_force_conformal.py` | conformal intervals on the member forces |
| `python learning_curve.py`, `python ../experiments/e6_width_sweep.py` | learning curves, split stability, network-width sweep |
| `python extrapolation.py`, `python ../experiments/e8_ood_detection_curve.py` | out-of-domain accuracy and detection curve |
| `python ../experiments/e1_config_change.py`, `python ../experiments/e1_plot.py` | retraining for a changed loading configuration |
| `python design_optimization.py` (needs `solver/` installed) | reliability-aware reinforcement design |
| `python make_parity.py`, `python make_figures.py`, `python validate_experimental.py` | parity plot; pier-cap check of solver and surrogate |
| `cd solver && npm run validate:piercaps` | solver vs pier caps (mean ratio 1.39, CoV 0.11) |
| `cd solver && npm run validate:deepbeams` | solver vs Li et al. deep beams (mean ratio 0.45, CoV 0.09) |
| `python ../experiments/e4_plot.py` | the two experimental series side by side |

Retraining from scratch: `python train.py --archetype deepBeam` writes
`runs/deepBeam/model.pt` (this overwrites the trained checkpoint; copy it
first). Regenerating the dataset: `cd solver && npm run dataset`.

## Notes

* The solver is a discrete strut and tie solver with the CSFM constitutive
  laws, not the continuum CSFM. Its bias against the two experimental series
  differs in sign: conservative by a mean factor of 1.39 on the pier caps,
  unconservative by a factor of 2.2 on the thin deep beams. The surrogate
  reproduces the solver, not the measured capacity.
* Designs that do not fail within the analysed load range carry the label
  `failureLoadFactor = 3.0`.
* The datasets are gzipped JSON; the loaders read them directly.
